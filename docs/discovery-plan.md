# Show discovery implementation plan

Approved: coverage-first discovery with exact source retrieval, no embeddings/vector database, no live LLM tests. Existing manual generation, saved drafts, exports and connection state must remain intact.

Architecture: discovery.py owns pure planning, source window retrieval, deterministic checks/dedup, ranking and resumable runs. server.py adds separate preview/start/resume/view/check routes through existing durable jobs and call budget guards. Frontend adds a separate Discover screen and reads run views without replacing manual drafts. No destructive schema changes.

Tasks: (1) tests first for 50/100 episode coverage, long dialogue windows, scope, caching, resume, invalid candidates and ranking. (2) implement discovery module. (3) add endpoints with persisted run ID before model work and cancellation checkpoints through save/call. (4) add preview with request/budget range and explicit start, coverage/results/history/resume and local exports. (5) offline full regression + browser checks. Do not connect Gemini or run paid probes.

Shared backend contract: plan_discovery(p,body,model) -> plan dict {selected_ids,structure:'continuous'|'stitched'|'either',limit:1..30,quantity:'auto'|'cap',minimum,maximum,emphasis,model,windows:[{id,episode_id,events:[],start,end}],batches:[{id,window_ids:[]}],estimated_calls:{minimum,maximum},...}. Every selected event must appear in windows; complete dialogue turns preserved, overlapping windows allowed, source estimates bounded. Plan includes upper request count with one targeted stitching request and bounded reviews, no silent automatic retries beyond call adapter.
new_run(plan) -> {id,status,plan,coverage:[],candidates:[],shortlist:[],rejections:[],review_cursor:0,...}. run_discovery(p,run,call,save,material) mutates only run and p.discovery_cache, checkpoint save(p); p.discovery_runs contains run before invocation. select model in cache keys. Each call callback signature call(pid,stage,prompt), returns dict. Scan returns {candidates:[draft],opportunities:[{key,reason,event_ids:[]}]}; draft matches existing workflow.DRAFT with id assigned by server/module. Scan does discovery+draft in same call. Review returns {results:[{promo_id,narrative:{standalone,escalation,cliffhanger,coherent},rubric:[{criterion,score,reason}],review_notes}]}. Validate hard source checks before review (never fabricate score approval), review uses clip-only evidence without generator context. Rankings only fully eligible reviewed cuts. Group shortlist entries {id,title,opportunity,source_ids,variations:[draft],posting_priority,posting_reason}. No forced N; cap chooses up toN. Review priority raw rough fields not treated as approved score. Coverage differentiates scanned, no candidate, pending; full scan does not claim exhaustive discovery.

Discovery endpoints: POST /api/projects/{pid}/discovery/preview -> plan summary excludes event text, plus cost upper estimate; POST /discovery -> {job_id,run_id}; POST /discovery/{rid}/resume -> same; GET /discovery/{rid}/view -> project copy with shortlist groups, synthetic compatible brief, discovery_view=rid, original drafts untouched; POST /discovery/{rid}/spoiler-check -> single batch assessment of run shortlist; GET /discovery/{rid}/export -> JSON source-backed report. Store p.discovery_runs as list. No auto-publish into p.groups.
